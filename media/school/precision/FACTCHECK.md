## Other notes

- Typed numbers that should be tokens: "five thousand" (row 12; `stagnation.rows.0.n`), "2 apart" (row 13; `stagnation.rows.0.spacingAtStuck`), "one part in ten thousand" (row 9; `near110.requiredRel`). "64 terms" in the row 22 rewording should come from `matmul.rows.1.K` or the model config.
- `evidence.json` `nvidia` claims "fp16 or bf16 inputs with fp32 accumulators". The guide also lists fp16 inputs with fp16 accumulators; the claim is incomplete. `facts.sources.nvidia.cudaGuide` already records "a float (or __half) accumulator", so the film line in row 15 lost what facts had. The section number 5.4.11.6, the title "Element Types and Matrix Sizes" and the version 13.4.2 (page updated 10 September 2026) are right.
- `evidence.json` `micikevicius2018` still says "to be read by the fact-check". Its claim matches the abstract and sections 3.1 to 3.3. The arXiv PDF lists Narang, Diamos and Elsen (Baidu) before Micikevicius and colleagues (NVIDIA), with equal-contribution marks; the arXiv metadata and common citation lead with Micikevicius, so the film's naming is fine.
- `facts.near110.note.where` says the raw-native note is on branch `diag/rr-tensor-core` at commit 6c06e62 and "not in the working tree". The note is now on public `main` at the URL `evidence.json` gives, byte-identical to commit 6c06e62; the branch name returns 404. The quoted fields in `facts.near110.note` match the note. The film quotes none of the note's own figures, which is right: `near110.verdict` already flags the note's "about 1e-3" as an order of magnitude (exact 5.68e-4 spacing, 2.84e-4 worst rounding).
- The `ieee754` source was not read (paywalled); the parameters were checked against ISO/IEC TS 18661-3 and against every fp16 bit pattern. This is disclosed in `evidence.json` and is acceptable for these figures.
- Voice: no intent is given to models or chips. Row 23 is the over-claim from a tiny model; row 22 is the causal slip.
