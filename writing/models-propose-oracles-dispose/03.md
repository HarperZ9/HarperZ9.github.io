## 4. The boundary, crossed live

Buildlang can call out to a model over a socket, a connection between two programs, and that makes the boundary concrete enough to enforce in code. The receipt layer, the part of the compiler that issues and checks receipts, flat out refuses to emit or verify a scientific receipt over any program that observes a model, meaning any program that calls one. A scientific receipt is the ordinary kind from section 2. The refusal has its own name, which marks the run as inadmissible as evidence. That run still has value. It counts as a proposal, and a proposal gets a different document: a boundary receipt, sealed at the point where data passed between the two programs. It records only that the exchange happened at this boundary under this seal. It makes no claim that the model was right.

This month I watched the loop close live, the full trip from proposal to decision. A local model, one running on the machine itself, proposed a completion, a piece of generated text, over a real socket. The shim on the far side, a small piece of connecting code, sealed a boundary receipt over the exchange. The verifier accepted that receipt and refused a tampered copy because the seal no longer matched. Then a model-free kernel, a small checking program with no model inside it, did the scientific judging under an ordinary receipt of its own. A chain bound the proposal and the disposition into one tamper-evident bundle, and each receipt in it was re-verified on its own. Tampering with the model's receipt broke the chain by name. The proposal and the judgment ended up in one evidence bundle, kept apart, and that separation got tested from both sides.

The branch that carries this end to end, a working copy of the code kept apart from the main project, is in review as I write and hasn't been merged. So what I'm describing is a demonstration, and no shipped release contains it yet. That gap, between a demo and a release, is what this essay is about.

*Update, 3 October 2026: the receipt work described here has since shipped. The Corrections section at the end names the release.*
