# Models Propose, Oracles Dispose

## A generated claim is a proposal. Nothing a model produces becomes evidence until something the model does not control has had its chance to say no.

*Zain Dana Harper, July 2026*

## In short

AI models now produce drafts and answers at almost no cost. This essay argues that none of that output should count as evidence until an independent check, one the model does not control, has had the chance to reject it. The title calls that check an oracle. A rejection stops the claim and is written down when it happens. This matters because people cite and build on what they trust, so an unchecked claim passes into every later use. Sections 2 to 4 show how I build that check into my own software, and section 5 sets out where I stand on models and how the rule binds me too. The code is public at [github.com/HarperZ9/buildlang](https://github.com/HarperZ9/buildlang) for anyone who wants to check it.

## 1. The rule

The rule fits in four words: models propose, oracles dispose. An oracle, in this essay, is the independent check that decides. To dispose, in the old sense the title borrows, is to settle the outcome, and the disposition is that final decision. Everything else I have to say is commentary on where those four words draw the line.

A model may draft, translate, summarize, and search, and I welcome all of that in my shop. None of it is evidence. The evidence layer is any place where later work trusts a result without checking it again, where claims get cited and built on.

Between a model's output and that layer there has to stand an independent check that can say no, a mechanism the proposer does not control. A reviewer skimming for tone falls outside that definition, and so does a second model, because a second model agreeing is a second proposal. When the check refuses, the claim stops at the door. The refusal is written down when it happens.

The phrasing sits deliberately close to the old proverb "Man proposes, God disposes," because the structure is the old structure: one party proposes, and another decides. A tireless proposer can be brilliant and right most of the time, and the disposition still belongs to something else. Machines changed the economics. Proposals used to be scarce, so treating a confident one as halfway to a finding was survivable. Now proposals are nearly free, and a discipline calibrated for scarce proposals fails quietly when they arrive in bulk.

Trust without a second check is what makes the evidence layer a layer and keeps it from being a pile. Once a generated result lands there on its own authority, every later user inherits a claim nobody ruled on, and the inheritance compounds with each reuse. So the rule holds at the door, built into the structure, and it keeps holding when people forget to be careful.

## 2. A receipt that re-derives

The place I hold this line hardest right now is a compiler, the program that turns code into software a computer can run. It compiles buildlang, a programming language whose code is public. A program built with it prints its results and can also emit a receipt: a sealed record of what ran, what came out, and which invariant the run was checked against. Sealed means locked with a digital fingerprint, so any later change to the record shows. An invariant is a condition the run must satisfy.

The verifier, a separate program that checks receipts, re-derives the result, which means it works the result out again. It recomputes whatever the sealed facts allow and compares the answers. It checks the invariant again, and it re-runs the program to compare the exit status, the code a program reports when it finishes, with the sealed one. Agreement is a verdict, with the full weight of one.

One record format holds this shape across five kinds of computation: fully deterministic runs, closed-form probability, seeded randomness, sampled estimates, and budgeted search. In plain terms, one receipt format works whether a program gives the same answer every time, works out an exact probability by formula, uses random numbers that can be replayed, estimates an answer from many random trials, or searches for the best answer it can find within a fixed budget. The sampled cases carry their sample counts inside the seal, because an estimate that hides how many samples it rests on cannot be checked.

Some facts cannot be re-derived exactly, and for those the honest move is to admit it. Wall-clock time, how long the run took by the clock, is the plain example. The verifier measures it again, then reports the sealed value and the fresh one side by side without forcing them to agree. Calling a second measurement a re-derivation would be the exact overclaim this whole apparatus exists to refuse. Checking this way is slower than trust and more annoying than confidence, and that slowness is the discipline itself. A receipt states what was checked and how, and nothing stronger, so a null result, a check that confirmed nothing, is reported as exactly that.
