Run a team of AI agents from one request.

Forum runs teams of AI agents. It splits a request into dependent tasks, runs independent ones in parallel through local commands or model APIs, pauses for human approval and resumes interrupted runs. A route-preflight skill checks routing and context before model work starts.

See it work, step by step: an animated walkthrough with the real commands and output from the repository.

What a run does

Forum picks a specialist track for the request, turns it into a plan of dependent tasks, runs independent tasks in parallel, checks each result against its instruction, and assembles one answer. Each step goes into a hash-chained ledger, so you can replay the run and see which model produced which result.

budgets cap a run by model calls and wall-clock time
escalation retry a failed task on a stronger model
intent check flag an answer that no longer covers the request
delivery pass shorten a verbose answer, kept only if it still covers the request
resume restart a crashed run from its last checkpoint, reusing finished tasks
approval gates pause for a person to approve, edit or reject before work continues

Executors can drive any command, any OpenAI-compatible server or the Anthropic API. The engine is Python with no third-party runtime dependency and runs on your machine as a CLI or an HTTP and MCP daemon.

Install and try it

$ pip install forum-engine==1.15.1
$ python examples/demo.py   # routes, plans, runs, then checks the ledger

Watch the recorded workflow: one request becomes three dependency waves, three validator passes, 19 ledger entries and three checkpoints. Each example under examples/ shows one feature offline.

The forum-route-preflight skill (v0.1.0) is for agent hosts that load local skills. With the Forum CLI or a source checkout available, it checks route selection, context pressure and runtime readiness before model work starts. It never runs the command and always returns safe_to_submit=false, leaving the go-ahead to you or your host policy.

Install 1.15.1 or later: every earlier release is inside the range of one of the two Forum advisories listed on the Security page. Upgrading from 1.14 changes a few defaults. By default, forum serve needs the token it prints at startup. Each command runs in a new private empty folder, so give it full paths, because a relative path such as --cmd "python adapter.py" no longer resolves. A command also sees a short environment; FORUM_CHILD_ENV names any extra variable it needs. An MCP client can approve, edit or reject a gate only when forum mcp starts with --allow-gate-decisions. The 1.15.0 and 1.15.1 release notes list every upgrade change.

Version 1.15.0, released on 27 September 2026, fixes the high-severity advisory GHSA-36gv-h885-fmjf. Each command now starts in a private empty folder with a short environment, and a gate decision counts only for the gate it resolves. Version 1.15.1, released the same day, fixes GHSA-h6qh-49hv-4xcg (high), a gap in the 1.15.0 working-folder guard. The guard keeps the folder of the running interpreter on PATH, and on Windows the Windows, System32 and SysWOW64 folders. When Forum runs in a filesystem root or in a folder that holds the home folder, it drops only the entry naming that folder itself. Every version before 1.15.1 is affected by one of the two, so install 1.15.1 or later.
