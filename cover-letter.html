Letter of Introduction

Zain Dana Harper. Systems engineer, Seattle.

Seattle, Washingtonzaindharper@gmail.comgithub.com/HarperZ9

Hello,

I build evaluation environments and developer tools that make an AI system's work easier to inspect, reproduce, and challenge.

My strongest current example is Terminal State Fixtures. Its first environment enumerates 324 reachable run records and scores the terminal state of the work rather than trusting what a transcript says happened. A second environment adds 337 component cases and about 5,000 frozen probe comparisons. The datasets, reference scorers, and tests are public, so the claims can be re-derived instead of accepted from this letter.

I also built Flywheel, a Python and Flutter platform for model routing, gated agent actions, and offline-recheckable tool-call receipts, and BuildLang, a Rust systems-language toolchain where filesystem, network, and foreign-call capabilities appear in the type system. As of 2026-08-25, 31 engineering pull requests had merged across 26 third-party repositories. Those contributions show how I enter unfamiliar codebases, reproduce a problem, and work within a maintainer's standard.

The same practice extends beyond software. I have worked in technical support, documentation and product operations, and eleven years of Seattle-area field coordination. Across those settings, the useful skill is consistent: map the moving parts, make changing conditions explicit, produce a reliable artifact, and explain the next step clearly.

This public letter is intentionally general. For a specific role I tailor the evidence, explain material gaps plainly, and connect the work to the organization's actual problem. I would welcome that conversation.

Thank you,
Zain Dana Harper
