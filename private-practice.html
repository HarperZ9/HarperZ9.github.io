Eight-system index.

Seed Seed is a 59-module C++23 security-assessment engine with 3,065 tests. It supports controlled labs, detection engineering, training, and authorized assessment through synthetic demonstrations, scope manifests, native tests, interop adapters, and action receipts.
Array Array orchestrates authorized offensive-security campaigns. It plans digest-sealed waves, holds execution behind single-use time-limited approval, supervises registered assessment tools through an independent containment monitor, and records decisions, cleanup, findings, and evidence in a verifiable ledger.
Sofer Sofer is the private-line orchestration and operational suite. It coordinates specialist agents, model backends, assessment probes, intelligence and scheduling systems, multi-stage workflows, tool execution, admission decisions, and receipt-backed handoffs across security, infrastructure, investigative, legal, safety, and high-consequence technical domains.
Isomorph Isomorph is an authorized AI red-team harness for the inference boundary. It measures classifier and refusal behavior, transforms and retries requests through escalating reformulation layers, records which approaches succeed for each provider, and analyzes the stability of those controls. Its mechanisms are jailbreak-class; authorization and research scope determine legitimate use.
Bounds Bounds verifies trust across agent actions, runtime observations, and releases. It detects intent drift and unsupported history claims, runs file, git, claim, secret, and fixture sensors through explicit guard layers, emits evidence-backed receipts, and builds release inventories and tamper-evident proof chains.
Kun Kun maintains local access-recovery memory for owned systems through path-only receipts, redacted diagnostics, rotation notes, and operator runbooks without storing raw credentials.
ORCA Operate private-line assessments by managing engagement state, executing descriptor-backed modules, cataloging findings and artifacts, producing reports and portable bundles, and recording release provenance.
Gate Gate is Sofer's private release-check subsystem. Its Python command-line tools validate readiness, operations, engagement, deliverable, and release manifests; required source, documentation, and test paths; configured controls; and verification-command results. Gate returns pass or fail findings, writes hashed JSON receipts, and blocks advancement when required evidence or controls are missing.

Purpose Navigate eight distinct products whose campaign, assessment, orchestration, model-testing, trust, recovery, runtime, and release responsibilities stay explicit. Shared engagements do not make them one product.
Problem High-consequence work requires real operational tooling and a record that preserves authority, execution state, findings, cleanup, provenance, and release decisions.
Components Campaign control, native assessment modules, specialist-agent orchestration, inference-boundary testing, trust sensors, operator runtime, release verification, and verifiable ledgers.
Bounded workflow Define the authority, define the surface, run only within that surface, record the result, and stop when the written scope ends.
Intended users Lawful organizations that need disciplined adversarial evaluation, sensitive-system review, market-risk tooling review, or high-assurance technical evidence.
Testing approach Native test suites, synthetic fixtures, deterministic replay, digest-sealed plans, time-limited approval, containment monitors, artifact hashes, runtime sensors, and release proof chains.
Non-sensitive deployment model Run inside the authorized environment or as an offline review packet. Public material excludes protected infrastructure, counterparties, and environment facts.
Limitations No public release, no public source, no public walkthrough, and no claim that any system is accepted by a third party.
Engagement boundary A written scope and lawful authority are prerequisites. A request without those facts receives only public material.
