Bounds · private · superproject · proprietary · trust verification

Agents drift. Environments change. Releases ship unchecked.

An agent that was safe at session start can drift by session end. A runtime environment that passed validation at deploy can change underneath the running process. A release pipeline that checks syntax and types can ship code that violates trust boundaries the type system cannot express. Bounds catches these failures.

Each verification produces a finding or a pass. Passes are recorded in the proof index alongside findings, so the absence of a check is itself visible.

Four verification scopes.

Agent intent-drift auditing Monitors agent sessions for behavioral divergence from stated intent. Catches capability escalation, scope creep, and unauthorized tool use. Each audit produces a drift finding or a clean receipt.
Runtime sensors Detect environmental changes during execution: filesystem mutations, network state changes, process tree modifications, credential access patterns. Sensor data feeds the guard layers.
Guard layers Policy enforcement points that consume sensor data and agent audit results. Each guard layer defines a boundary condition and an enforcement action (warn, block, abort, revoke).
Release-readiness scanning Scans a release candidate against trust criteria that go beyond compilation and test results: secret presence, dependency provenance, documentation coverage, boundary language. Integrated with the Aleph Checkpoint release gate.

Spec.

Scopes
Agent sessions, runtime environments, release pipelines, proof chains. Each scope has its own sensor/guard/audit stack.
Sensors
Filesystem, network, process tree, credential access. Pluggable sensor interface for domain-specific monitoring.
Guards
Policy enforcement with four actions: warn, block, abort, revoke. Guards compose with AND/OR logic.
Proof index
Records every check (pass or finding) with timestamp, scope, operator, and evidence hash. The index makes missing checks visible.
Sources
Consolidated from warden-agent-audit (6), warden-sensorium (9), and warden-release-assurance (7). Source repos archived.
Distribution
Private repository. Available to organizations running agent-heavy or release-gated workflows.
