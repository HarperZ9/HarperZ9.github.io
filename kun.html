Access recovery without exposing secrets.

Kun is a local access-recovery vault. It stores redacted diagnostics, rotation notes, and operator runbooks. It records where credentials live, never what they contain. Path-only, read-only receipts.

The vault knows the path to the key. It does not hold the key.

Kun · private · local-only · push-blocked · proprietary

Recovery documentation rots or leaks. Pick one problem and solve it.

Credential recovery is a documentation problem. Write the recovery steps in a doc and it becomes stale. Put credentials in the doc and it becomes a liability. Kun solves the first problem without creating the second: it records paths, rotation schedules, and recovery procedures, but never stores the credentials themselves.

The vault is local-only. It cannot be pushed to a remote. Every entry is a receipt that records what was accessed, when, and by whom, without containing the accessed material.

What it stores.

Recovery paths Where each credential lives: which vault, which key path, which rotation schedule. The path to the secret, never the secret itself.
Rotation notes When each credential was last rotated, what triggered the rotation, and what the next rotation window is. Procedural memory for the operator.
Redacted diagnostics When access fails, the diagnostic captures the failure mode and recovery path without capturing the credential or the protected resource content.
Operator runbooks Step-by-step recovery procedures. Each runbook is a sequence of actions with expected outcomes. Tested against the real recovery path, documented in the vault.

The boundary is the design.

What Kun never does

Stores raw credentials. Transmits secrets over a network. Pushes to a remote repository. Exposes credential values in receipts, logs, or diagnostics. The local-only, push-blocked constraint is enforced at the git level: the repository is configured to reject push operations to any remote.

Spec.

Storage
Local filesystem. Git-tracked for history and rollback. Push to any remote is blocked by configuration.
Receipts
Path-only, read-only. Each receipt records the access path and timestamp without containing the accessed value.
Diagnostics
Redacted by design. Failure mode and recovery path captured; credential values and protected content excluded.
Distribution
Private repository. Local-only operation. Cannot be cloned from a remote; must be initialized locally.

State of the work, August 2026.

The vault is operational with redacted diagnostics, rotation tracking, and operator runbooks. Push-blocking is enforced at the git configuration level. The credential vault flag is checked by the Aleph Checkpoint release gate.
