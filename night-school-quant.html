Everything the film says

Quantisation

Quantisation. Fewer bits per number.

Every number in our model is stored in 32 bits. Big models have billions of numbers, so the memory adds up fast. Tonight Tallow stores the weights in fewer bits and measures what the model loses.

A smaller palette

Think of a painter with fewer paints. With 255 shades a picture looks smooth. With 15, you start to see bands. With 3, you see mostly bands.

Quantising a table of weights is the same move. Pick a scale, divide every number by it, and round to the nearest of a few levels. At 4 bits our scheme has 15 levels; at 2 bits, only 3.

To use the table again, multiply back by the scale. Every number comes back to its nearest level, off by up to half a step.

What it saves

Our model takes 83,456 bytes in 32-bit numbers. At 4 bits, with one scale for each output of each table, it takes 15,376: 18 percent of the size.

What it costs

Score every version on the same 1,024 held-out rows. The full model's loss is 0.6676.

At 8 bits per number, one scale per output: 0.6677. At 6: 0.6685. At 4: 0.6754. At 3: 0.7249. At 2 bits: 3.48, and the model is broken.

Four bits instead of thirty-two. How much worse is the loss? (the film pauses here)

With one scale for each whole table instead of each output, it breaks sooner: 1.59 already at 3 bits.

Where it hurts

One scale has to cover a table's biggest number. If a few numbers are much bigger than the rest, the steps get wide, and every small number is rounded coarsely.

Quantise one table at a time to 4 bits, with one scale for the whole table, and see which one hurts. The readout, the table that turns the model's last list of numbers into word scores, costs the most: 0.0276 nats on its own.

Tim Dettmers and colleagues found in 2022 that in large models, once the activations are stored in 8 bits too, the trouble comes from a few huge values in them. Activations are the numbers flowing between tables. We left those in full precision here, so that part of the story does not show.

Rounding with care

Rounding each number on its own throws away the fact that they work together. GPTQ, from Elias Frantar and colleagues in 2023, rounds the numbers of a table one input column at a time and nudges the ones not yet rounded to make up for the error. It uses a small sample of text to see which errors matter.

At 4 bits with one scale per output, plain rounding raises the loss by 0.0078. GPTQ raises it by 0.0028, roughly a third as much.

It is not magic. At 2 bits with one scale per table, both versions are broken, and GPTQ comes out worse.

Goodnight

Fewer bits per number is how large models fit on smaller machines. Our model has only 83,456 bytes of numbers, and large ones behave differently, so how few bits you can get away with has to be measured on the model you have.
